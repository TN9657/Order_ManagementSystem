ORDER MANAGEMENT DASHBOARD — COMPLETE IMPLEMENTATION PROMPT
ROLE
Act as a senior full-stack software engineer and system architect.
Build a production-quality but appropriately scoped Order Management Dashboard for an Operations Team.
The application must be:
•	Correct
•	Simple
•	Maintainable
•	Scalable
•	Performant
•	Easy to understand
•	Properly tested
•	Properly documented
Do not build an Amazon-like customer-facing e-commerce platform. This is primarily an internal operations/order-management application.
________________________________________
1. CORE OBJECTIVE
Build an internal Order Management Dashboard that allows an operations user to:
•	View orders
•	Search orders by customer
•	Filter orders by status
•	Sort orders
•	Paginate large order datasets
•	View customer-level order activity
•	View customer information
•	Create new orders
•	View order details
•	Update order status
•	Cancel orders where appropriate
•	View dashboard KPIs
•	Handle invalid input and failures gracefully
The system should be designed with future scalability in mind.
Expected future scale:
•	5M+ orders
•	Hundreds of thousands of customers
The application does not need to generate 5M records for this assignment.

7. ORDER STATUS
An order can have exactly one of:
pending
completed
cancelled
Use an appropriate PostgreSQL/SQLAlchemy representation.
Do not allow arbitrary status values.
Document valid status transitions.
Recommended rules:
pending → completed
pending → cancelled
Do not allow:
cancelled → completed
completed → pending
completed → cancelled
unless there is a clearly documented business reason.
